# Apartment: 빨간 사과 두 개 탐색 및 복귀

`worlds/apartment.wbt`의 `tb3_rescue` 컨트롤러입니다. 사전 지도, 사과 좌표,
GPS, Supervisor, Webots recognition 정답 정보는 사용하지 않습니다.
사용자 맵의 사과·가구·사람 배치를 그대로 사용합니다.

## 인지 → 계획 → 행동

### 인지
- 엔코더 원시 오도메트리와 연속 LiDAR 스캔의 point-to-line ICP 위치 추정을
  별도로 유지합니다. ICP는 정지 가설과 엔코더 예측 가설을 모두 검사합니다.
- 실제 TurtleBot3 extensionSlot 위치를 반영한 카메라/LiDAR 좌표 변환.
- YOLO의 apple 클래스 + 중심부 빨강 비율 45% 이상 + 종횡비/영상 경계 검사.
- 1초 이상 끊기지 않은 관측 중 YOLO 사과 검출 3회가 있으면 접근 대상 사과로
  식별합니다. 영상 추정 거리 0.80m 이내에서 YOLO로 재확인하면 확정·방문을 동시에 기록합니다.
- 녹색·보라색·주황색 사과를 색상 필터로 제외. 사람·병·컵 검출과 겹치는
  후보도 제외합니다. 색상만 검출된 빨간 캔·소화기는 절대 사과로 확정하지 않습니다.
- 색상만 검출된 후보는 접근·주시 목표로 사용하지 않습니다. YOLO 사과 검출이
  최소 1회 있었던 미확정 후보만 최대 6초간 재관측하고, 실패하면 90초간 보류합니다.
- 사람의 영상 방향과 LiDAR 거리를 결합해 위치/속도를 추정하고 0.8초 후 만료.
  사람 방향의 현재 LiDAR 반사점은 정적 벽으로 누적하지 않습니다.

### 계획
- log-odds 점유 지도와 로봇 여유 공간을 반영한 A* 경로 탐색.
- 한 번의 Dijkstra 탐색으로 도달 가능한 탐색 경계들의 실제 이동 거리를 비교.
  정보량과 방문 이력도 반영해 여러 방의 미탐색 공간을 선택합니다.
- LiDAR로 파악했지만 카메라로 보지 못한 바닥에도 관측 지점을 생성합니다.
- 시작 시에만 360도 관측(최대 13초). 이후에는 이전 관측 종료 후 22초 이상,
  이전 관측 위치에서 1m 이상 이동, 반경 2m 안의 가려지지 않은 알려진 바닥 중
  카메라 미관측 비율 20% 이상·16셀 이상이라는 조건을 모두 만족할 때만
  미관측 바닥이 더 많은 쪽으로 최대 180도 관측합니다(최대 7초).
  진행 중인 관측은 목표 도착으로 재시작하지 않으며 사과 접근·재관측 목표가
  생기면 관측을 중단하고 이동을 우선합니다.
- 확정된 미방문 사과를 우선하되 도달 불가능하거나 25초간 진전 없는 목표는
  잠시 보류하고 다른 목표를 선택합니다.
- 경로 단순화는 미탐색 셀이나 장애물 모서리를 가로지르지 않습니다.
- 복귀 경로를 만들기 위해 장애물이나 지도 정보를 강제로 지우지 않습니다.

### 행동 및 완료 조건
- 실시간 LiDAR와 사람의 예측 위치에 대해 속도·회전 후보 궤적을 검사합니다.
  사람과는 예측 거리 0.70m를 유지하도록 후보를 제외합니다.
- 휠 속도 제한 시 좌우 비율 보존, 시간 간격을 반영한 가속 제한.
- 가까운 장애물·사람, 센서 장애, 유효 이동 후보 없음에는 즉시 정지.
  제자리 회전은 0.18m, 이동은 0.24m의 궤적 여유 거리를 적용해 벽 근처에서
  안전한 방향 전환까지 불필요하게 막히는 상황을 줄입니다.
- 가까운 빨간 사과의 검출·확정 시 `apples`와 `visited`가 함께 1 증가합니다.
  기준은 영상 추정 거리 0.80m 이내와 현재 YOLO 사과 검출입니다. 지도상 거리나
  별도의 방문 판정은 추가로 요구하지 않습니다. 먼 사과는 접근 후보로 유지하며
  두 카운터에 아직 넣지 않습니다. 색상 후보만으로는 집계하지 않습니다.
- 이미 방문한 위치로부터 0.75m 이내의 중복 검출은 다시 집계하지 않습니다.
- 두 사과에 접근한 후 시작점으로 복귀하고, 추정 위치 오차 0.22m 미만에서
  즉시 정지하여 `COMPLETE`가 됩니다. 발견만 하고 복귀하지 않습니다.

## 카펫·단차 걸림 감지 및 복구

`motion_guard.py`가 최근 약 2초 동안의 이동 명령, 엔코더 이동량, LiDAR 실측
이동량을 비교합니다. 원시 오도메트리와 위치 추정값의 전체 누적 차이만으로
판단하지 않으므로 장시간 주행의 일반적인 누적 오차와 걸림을 구분합니다.

- 헛바퀴: 엔코더 이동 12cm 초과, 실측 이동이 엔코더의 30% 미만,
  이동량 차이 10cm 초과가 지속되면 걸림으로 판단합니다.
- 모터 정체: 전진 명령은 누적 16cm 이상인데 엔코더와 실측 이동이 모두
  거의 없는 경우도 감지합니다. 의도적인 정지와 제자리 회전은 제외합니다.
- 대응점 부족, 평행 벽만 보이는 등 위치를 결정하기 어려운 스캔은
  '정지했다'는 증거로 사용하지 않습니다. 위치 추정이 2초 이상 불확실하면 정지합니다.
- 복구 순서: 0.3초 정지 → 6cm/s로 최대 약 18cm 후진 → 약 25도 방향 조정
  → 경로 재계획. 후진은 최대 3초, 회전은 최대 2초로 제한합니다.
- 후진·회전 전과 도중에 LiDAR 전체 방향과 사람의 예측 위치를 검사합니다.
  후방이 막혔거나 실제 탈출 진전이 없으면 `RECOVERY_BLOCKED`로 정지합니다.
  같은 부근에서 성공 후 다시 걸리는 복구 시도도 최대 3회로 제한합니다.
- 걸린 방향의 작은 구역을 120초간 경로에서 제외합니다. 이것은 정적 벽이 아닌
  일시적인 회피 구역이며, 카펫 높이나 원본 맵의 충돌 형상을 바꾸지 않습니다.
- 위치 정합을 신뢰할 수 없거나 복구 중일 때에는 지도와 사과 위치를 갱신하지
  않습니다. 복구 거리·회전 완료는 엔코더 예측 대신 마지막 LiDAR 확정 위치로 판단합니다.

결과 JSON의 `odometry_pose_m_rad`, `motion_evidence`, `scan_quality`, `recovery`를
확인하세요. `recovery.reason`은 후방 막힘, 후진 진전 없음, 위치 추정 불확실,
재시도 한도 등을 구분합니다. 안전하게 탈출할 공간이 없는 경우에는 위치를
조정하고 시뮬레이션을 재시작해야 합니다. 저가형 2D LiDAR는 차체 기울기 자체를
직접 측정하지 않으므로 모든 종류의 단차·전복에서 자동 탈출을 보장하지 않습니다.

## 실행

Webots R2025a에서 `worlds/apartment.wbt`를 열고 시뮬레이션을 초기화한 뒤
실행하세요. 실행 중인 컨트롤러에는 Python 파일 수정이 자동 반영되지 않습니다.

```powershell
uv venv .venv
uv pip install --python .venv\Scripts\python.exe -r requirements.txt
.venv\Scripts\python.exe -m unittest discover -s controllers/tb3_rescue -v
```

`runtime.ini`는 현재 프로젝트의 `.venv` 절대 경로를 사용합니다. 프로젝트를
다른 경로로 옮기면 COMMAND를 수정해야 합니다. 보행자 기본 컨트롤러는 Webots의
Python 설정을 사용하므로 해당 인터프리터도 실행 가능한지 확인하세요.

## 결과와 검증 범위

`mission_output/mission_result.json`과 `occupancy_map.pgm`은 상태 출력 시와
완료 시 갱신됩니다. 상태 출력 주기는 시뮬레이션 시간 기준 5초입니다.
`control_reason`, `stop_reason`, `inspection_goal`, `survey_remaining_rad`로
탐색·관측·장애물 정지의 원인을 확인할 수 있습니다. JSON의 `success: true`와 `state: COMPLETE`를 함께 확인하세요.
`targets`에는 각 사과의 마지막 관측과 접근 시각, `home_error_m`에는 추정 복귀
오차가 저장됩니다. 미완료 상태의 파일은 성공 결과가 아닙니다.

회귀 테스트는 색상/의미 분류 분리, 사람 추적과 회피, 미탐색 공간 우회,
복귀 지도 보존, 중복·오래된 관측 제외, 두 사과 접근 후 복귀 상태 전이를 검사합니다.
합성 영상과 가짜 검출기를 사용하는 테스트는 실제 YOLO 인식률을 보장하지 않습니다.
일반 COCO 모델이 사과를 놓치거나 다른 물체를 사과로 오분류할 가능성은 남아 있습니다.
소화기는 COCO 전용 클래스가 없으므로 클래스·색상·형태 검사로만 방어하며,
실제 장면에서 오인식이 남으면 해당 사과/캔/소화기 영상으로 추가 학습해야 합니다.

위치 추정에는 전역 루프 폐쇄가 없으므로 장시간 주행의 누적 오차가 남습니다.
복귀 오차는 센서 추정값이며 외부 정답 위치와 같다는 보장이 없습니다.
사람 회피 역시 영상 누락·급격한 이동·LiDAR 높이 밖 장애물까지 보장하지 않습니다.
실제 apartment 전체 임무의 성공은 Webots에서 완료 로그 및 결과로 별도 검증해야 합니다.

### 시작 소화기 주시 정지 수정 검증

- 색상만 검출된 물체의 접근·주시 목표 선택을 차단했습니다. 미확정 사과의
  재관측 시간과 시작 회전 시간을 제한하고, 안전한 제자리 회전의 여유 거리를
  이동 여유 거리와 분리했습니다.
- 해당 회귀 사례를 포함한 테스트 30개 통과.
- 별도 apartment 실행에서 15초에 `FOLLOW_PATH`, 추정 위치 (0.67, 0.27)m,
  20초에 (1.01, 1.02)m를 확인했습니다. 25초까지 `inspection_goal: null`로
  탐색을 이어갔습니다. 시간은 시뮬레이션 시간이며 전체 임무 성공 검증은 아닙니다.
- 코드 변경은 현재 실행 중인 컨트롤러에 자동 적용되지 않으므로 월드를 다시
  불러와 실행하세요. 시작 회전 관측은 시뮬레이션 시간 약 11초 소요됩니다.

### 카펫 걸림 수정 검증

- 총 42개 회귀 테스트 통과. 실제 변위 추정, 정지 상태의 헛바퀴, 모터 정체,
  정상 주행·회전, 불충분한 스캔, 후방 장애물·사람, 복구 실패 제한,
  일시적 회피 구역 만료, 엔코더만으로 복구 완료하지 않는 조건을 검사했습니다.
- 별도 apartment 실행에서 정상 탐색 60초 동안 불필요한 복구가 없었습니다.
- 원본 높이 카펫 경계 앞에서 시작한 시험은 카펫을 통과했고 걸림 오감지가
  없었습니다. 이 접근 각도에서는 사용자가 겪은 걸림 자체가 재현되지는 않았습니다.
- 재현 가능한 걸림을 만들기 위해 **검증용 복사본에서만** 카펫의 z를 -0.015에서
  0.015로 높였습니다. 원본 apartment와 카펫 PROTO는 변경하지 않았습니다.
- 시뮬레이션 4.16초에 최근 2.56초의 엔코더 0.4561m, LiDAR 0.0829m,
  차이 0.3732m로 걸림을 감지했습니다. `BRAKE → BACKUP → TURN → REPLAN`
  이후 실제 frontier 계획기를 사용해 10초에 `FOLLOW_PATH`, 15초에
  (0.25, 0.90)m 지점 관측, 30초에 (-0.19, 1.01)m까지 탐색 재개를 확인했습니다.
  좌표는 시험 시작점을 기준으로 한 LiDAR 추정값입니다.
- 이 검증은 걸림 감지·탈출·탐색 재개에 대한 시험이며 사과 두 개 접근 및
  복귀 임무 전체의 성공을 의미하지 않습니다.

### SURVEY 빈도 조정 검증

- 가까운 탐색 지점 연속 도착, 관측 간격 제한, 이미 관측한 방, 새 방의
  180도 관측·시간 제한, 사과 목표 우선 처리에 대한 회귀 검사 포함 46개 통과.
- 이번 빈도 조정은 단위 테스트로 검증했으며 변경 후 Webots 주행은 별도로 실행하지 않았습니다.

### 근접 장애물 정지 및 사람 시야 보완

- LiDAR 원점과 로봇 중심의 3cm 차이를 비상 정지 거리에도 반영했습니다.
- 근접 정지가 1초 지속되면, 모든 가까운 반사점에서 멀어지고 사람과도 안전한
  방향이 있을 때만 4cm/s로 짧게 탈출합니다. 15cm 하드 여유 거리, 최대 1.5초/6cm,
  같은 부근 최대 2회 제한을 적용하며 탈출 후 경로를 다시 계획합니다.
- SURVEY 간격은 22초·1m, 미관측 비율 20%로 조정했습니다. 최대 180도/7초 제한은 유지합니다.
- 기존 RGB 카메라 한 대의 동일 YOLO 추론에서 사과와 사람을 함께 검출하고,
  사람 박스는 LiDAR와 융합합니다. 추가 카메라와 별도 사람용 추론은 제거했습니다.
  JSON의 `person_boxes`는 기존 영상의 사람 검출 수, `tracked_people`은 거리와
  융합된 추적 수입니다.
- 목표는 기존 센서만 사용해 다른 색 사과·빨간 유사 물품을 제외하고 빨간 사과
  두 개 각각에 접근한 뒤 시작점으로 복귀하는 것입니다. 사람 회피, 여러 방 탐색,
  걸림 복구는 이 임무를 보조하며 새로운 장치를 요구하지 않습니다.
- 사람 검출→LiDAR 추적 및 사과 오집계 방지를 포함한 회귀 테스트로 검증합니다.
  실제 영상 인식률과 전체 임무 완료는 별도의 Webots 주행 검증이 필요합니다.

### 가까운 사과 확정·방문 동시 집계

- `RedAppleDetector.VISIT_DISTANCE_M = 0.80`에서 근접 기준을 조절할 수 있습니다.
- 먼 사과 식별 → 접근 → 가까운 YOLO 재확인 → 두 카운터 동시 증가,
  같은 사과 중복 방지, 색상만으로 집계 금지, 두 개 집계 후 복귀 상태 전이를
  포함한 테스트를 통과했습니다. 이번 집계 변경 후 전체 Webots 임무는 재검증하지 않았습니다.

### 바닥의 낮은 장애물

- 기존 카메라의 같은 추론에서 모든 색 사과, 고양이, 병·컵 형태 용기를 검출합니다.
  목표 사과 역시 밟고 통과하지 않도록 처리합니다. 색상만 검출된 영역은 바닥 무늬와
  구분할 수 없어 장애물로 등록하지 않습니다. 화면 경계에 잘린 박스도 거리 추정에서 제외합니다.
- 영상 박스 하단과 기존 카메라 높이로 바닥 위치를 추정해 임시 장애물로 등록합니다.
  전역 경로와 근접 회피·탈출 제어에 반영하되 실제 LiDAR 위치 추정과 정적 지도에는
  합성 거리값을 넣지 않습니다. 고양이는 1.5초, 나머지는 20초 동안 재검출이 없으면 제거합니다.
- 캔 전용 학습 클래스는 없으므로 용기로 검출된 캔을 회피합니다.
  모든 캔의 검출을 보장하지 않으며, 바닥 위치 추정은 로봇 기울기와 가림에 영향을 받습니다.
- 이전 낮은 물체 처리와 기존 임무 회귀 테스트 총 57개 통과. 이후 바닥 색상 오검출 수정은
  사용자 요청에 따라 테스트를 실행하지 않았으며, 실제 Webots 주행도 재검증하지 않았습니다.

### 꽃병의 사람 오인식으로 인한 정지

- 사람 검출은 사과의 0.20 임계값과 분리해 신뢰도 0.55 이상만 사용하고,
  같은 영역에서 더 높은 신뢰도로 검출된 꽃병·용기가 있으면 사람 판정을 제외합니다.
- `PERSON_TOO_CLOSE`에서도 예측한 주변 사람 거리가 계속 증가하는 방향에 한해서
  4cm/s로 최대 30cm/7.5초 이동할 수 있습니다. 35cm보다 가까운 사람이 있으면 정지하며,
  다른 사람의 70cm 안전거리와 LiDAR 충돌 검사는 유지합니다. 매 제어 주기 재검사합니다.
- 이 수정은 코드 문법만 확인했으며, 주행 및 인식률은 재검증하지 않았습니다.

### 근접 탈출 두 번 후 영구 정지 수정

- 기존 두 번의 1.5초/6cm 탈출 후 같은 위치에서 재시도를 영구 차단하던 조건을 제거했습니다.
  장애물 탈출은 회당 최대 4초/20cm이며, 두 번 이후에는 5초 쉬고 센서를 다시 평가합니다.
- 첫 시도는 직선 4cm/s, 이후에는 최대 6cm/s·0.45rad/s 곡선 이동도 비교합니다.
  모든 가까운 반사점에서 멀어지는지와 15cm 하드 여유 거리, 사람 거리 조건을 매번 검사합니다.
- 각 탈출 종료 시 Localization 이동량을 기록합니다. 이 동작 중에는 일반 복구로 중복
  전환하지 않습니다. 일반 복구는 현재 18cm 미만 거리를 거부하므로 영구 BLOCKED가 될 수 있습니다.
- 문법 확인만 수행했으며 실제 탈출 성공은 Webots에서 확인해야 합니다.

### 미탐험 구역 우선 탐색과 계산 정리

- 도달 가능한 미방문 구역 → 카메라 미확인 구역 → 재방문 순으로 탐색 목표를 선택합니다.
  주변 약 1.3m 구역의 방문 비율, 국소 탐색 경계 크기와 실제 경로 거리를 반영합니다.
  진행 중인 미확인 목표는 유지하며, 사과 접근·두 개 방문 후 귀환 우선순위는 그대로입니다.
- 기존 목표를 유지할 때 불필요한 경계 추출을 생략하고, 후보별 중복 정렬과 주변 영역
  재계산을 줄였습니다. 경로 유효성 검사는 별도 타이머로 0.5초마다 수행하며,
  근접 충돌·사람 회피 검사는 기존처럼 매 제어 주기 수행합니다.
- 반응형 탐색도 미방문·미확인 방향을 우대하고 LiDAR 무반사(inf)를 열린 공간으로 처리합니다.
  사용자 요청에 따라 테스트는 실행하지 않았고 Python 문법만 확인했습니다.

### 구역별 꼼꼼한 탐색

- 알려진 주행 가능 지도의 좁은 연결부를 분리해 방을 근사한 구역을 만듭니다.
  실제 방 이름이나 월드 좌표를 사용하지 않으므로 열린 거실·주방은 한 구역이 될 수 있습니다.
- 현재 구역의 카메라 미확인 지점을 먼저 선택하고 유효한 후보가 없으면 다른 구역으로
  이동합니다. 120초가 지나면 다른 구역 후보를 우대해 한 공간에 고착되는 것을 줄입니다.
- 관측 완료는 카메라가 볼 수 있는 바닥 중 1.2m 이내로 좁혔습니다. 관측 후보의 이득은
  지도 장애물에 가려지지 않은 미확인 바닥을 기준으로 계산합니다. 후보별 계산은 재사용합니다.
- 사과 접근·집계·귀환, 기존 회피·복구·SURVEY 제한은 유지합니다. 문법만 확인했으며
  실제 방별 탐색 및 숨은 사과 발견률은 주행 검증 전입니다.
